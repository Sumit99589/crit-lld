crit: README and AI usage

Live: crit-lld.onrender.com
Code: github.com/Sumit99589/crit-lld

crit is a small practice platform for low-level design. Pick a problem, lay out your classes and the reasoning behind them, and get feedback graded against a fixed rubric that quotes your own design back to you. Revise, and the next review shows what you fixed.

Run it

Requires Node 22.13+. SQLite comes from Node's built-in node:sqlite, so nothing native needs compiling.

git clone https://github.com/Sumit99589/crit-lld && cd crit-lld
npm install
cp .env.example .env      # optional: add ANTHROPIC_API_KEY for the AI review
npm run build
npm start                 # http://localhost:4000

npm run dev               # development: API on :4000, Vite with hot reload on :5173
npm test                  # 62 server tests
npm run typecheck

Without an API key everything still works: each submission gets complete rule-based feedback, clearly labelled as such. A Dockerfile and a Render blueprint (render.yaml) are included for deployment.

  infra/        SQLite repositories (versioned writes) · InProcessQueue · logger

docs/    Research note, design note (PDF + Markdown), screenshots

Key decisions

  • Grade against a rubric, not a reference solution. LLD has many valid answers. Six criteria with four described levels make feedback comparable and actionable.
  • Facts before opinions. Deterministic checks run first, go to the model as verified facts, and cap its grades. The model must quote the design, and every quote is checked in code.
  • A structured canvas as the submission format: the smallest format that captures both structure (checkable) and reasoning (judgeable). New formats plug in behind SubmissionFormat; new evaluators behind Evaluator.
  • Evaluation never blocks and never loses work. Submit stores and enqueues (202). Evaluation is a state machine with a lease, retries and recovery. AI failure degrades to rules-only feedback instead of an error, and idempotency keys and content hashes prevent duplicates.
  • Cheap by design: Claude Haiku 5.5 at low effort, about $0.0015 per review, cached on identical input, with lifetime, daily and per-learner caps.

Limitations

  • No accounts: history is tied to an anonymous id in browser storage.
  • The deterministic checks are heuristic and English-centric, so they only produce findings and caps, never top grades.
  • The AI grader hasn't been calibrated against a hand-graded set yet.
  • Single process (SQLite and an in-process queue). The first piece to split out is the evaluation worker; see the design note.
  • The public demo runs on a free instance: it sleeps when idle (~50 s first load), resets its history on restart, and caps AI reviews at 30.

AI usage

The decisions where AI input mattered,
and what I did with it

I built this with Claude Code as a pair programmer. Most of the code was typed by the AI. I made the product and scope calls, steered the design, reviewed what came back, ran it, and pushed back where it didn't fit. Claude also did the first pass of the web research; the research note only cites pages it fetched and linked. Inside the product, a model (Claude Haiku 5.5) grades designs.

1. Stack: rejected Python

AI suggestedPython + FastAPI with a plain HTML/JS frontend, because domain classes read cleanly, there's no build step, and it uses little memory.

I decidedTypeScript end to end, with React + Tailwind. A practice tool lives or dies on whether people enjoy using it, and one language means the API types and the domain read the same way.

2. What the learner submits: a structured canvas

AI laid outfree text (easy, but almost nothing can be checked), a code skeleton (strongest evidence, but needs sandboxing and per-language parsing), and a structured "design canvas".

I chosethe canvas: the smallest format with both structure (classes, typed relationships, a requirement map, which rules can check) and reasoning (flow, decisions, response to change, which a reviewer can judge). It also gave us the live UML diagram for free.

3. Which model grades, and how much it may cost

Defaulta large model, for "better" feedback.

I asked forthe cheapest model, plus rule-based feedback that works on its own, because a practice tool must be cheap enough to use repeatedly. The result is Claude Haiku 5.5 at low effort, a cache keyed on the exact input, and daily, per-learner and lifetime caps (30 reviews in total on the public demo). A real review measured about 4k input and 2k output tokens, roughly $0.0015.

4. Not trusting the grader blindly

AI proposedthree guards: make the model quote the learner's design for every grade, verify every quote in code, and let deterministic facts cap its grades.

I kept all three.The TUM paper found LLM graders are generous to weak work, and I wanted feedback that points at evidence, not a number. In the first real run all 18 quotes verified, and a cap fired on a deliberately weak revision 1. The schema also asks for evidence before the band, the judge never sees its earlier verdicts, and "what you fixed" is computed by code.

5. The UI direction

I rejectedthe first, dark editorial design after using it, and asked for a light theme, a more professional typeface (Inter), a new logo, resizable workspace panes, and much less text. I also replaced the "How feedback works" section because it looked AI-generated; it is now a single row of four steps.

6. Where the AI's code was wrong, and how it was caught

  • TestsThe first Evaluation let a learner trigger "retry" on a running evaluation, because running → queued is a legal internal transition. The test suite caught it, and the fix guards learner retries explicitly.
  • ReviewScreenshot review caught that the composition diamonds were drawn backwards and hidden under class boxes, that the class editor overflowed on a 390px phone, and that the diagram was too small to read, which led to an "Expand" view.
  • SkippedSmooth-scroll (Lenis) came from the motion design guidelines I used. I left it out because it fights the scrollable panes of an editor app.
